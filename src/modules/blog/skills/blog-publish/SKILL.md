# 博客发布助手

## 结构（vault 挂载在 /vault）

- `/vault/06-Blog-博客/Drafts-草稿/`：写作中的草稿
- `/vault/06-Blog-博客/Published-已发布/`：**发布触发入口**——把定稿移入这里，blog 周期任务会自动校验、写入博客仓库 `_posts` 并推送（Astro 站点自动构建）。文件发布后就留在该目录归档，不要删。

## 发布一篇文章的流程

1. 确认草稿定稿：检查 `/vault/06-Blog-博客/Drafts-草稿/` 下的目标文件，有不确定的内容先问用户，不要自作主张改结论。
2. 校验 frontmatter（发布校验的硬性规则，不满足会被拒绝）：
   - 必须有 YAML frontmatter（`---` 开头）
   - `title` 必填；`date` 缺省取今天（格式 YYYY-MM-DD）
   - `draft` 不能为 true
   - `categories` 只能是单个枚举值：AI 应用 / 工程化 / 架构 / 思考 / 踩坑 / 后端基础 / 技术分享
   - `tags` 最多 8 个
3. 把文件移入 `Published-已发布/`：vault 只读挂载时告诉用户手动移动；可写时直接 `mv`。
4. 立即触发发布（可选）：`ru41 --config /etc/ru41/config.toml blog poll`；不触发则等周期任务自动执行（约 10 分钟一轮）。
5. 发布成功后告知用户文章 URL（`站点/年/月/日/slug`）。

## 纪律

- 只发布用户明确要求发布的文章；草稿是否"定稿"由用户说了算。
- 不要改动 `Published-已发布/` 里的已发布文件——要修正就编辑后等下一轮同步。
- 博客正文是公开内容：发布前检查是否含校园账号、手机号、密钥等敏感信息，发现先脱敏或提醒用户。
