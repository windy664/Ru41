# Obsidian 收件箱整理

1. 先读 Vault 根目录 `README.md`：目录地图、命名约定与分类边界以它为准；Vault 各目录不再单独放 README。
2. 只处理任务 prompt 中列出的收件箱变更文件，不翻阅 Vault 其他目录的私人笔记，除非为判断归档位置必须查看目录结构（列目录名即可，不读无关正文）。
3. 目录映射：
   - 知识 → `03-Knowledge-知识`
   - 项目 → `02-Projects-项目`
   - 机会（竞赛/科研/实习/奖学金等）→ `05-Opportunities-机会` 对应子目录
   - 课程 → `01-Courses-课程` 对应学期目录
   - 文章（博客选题/素材）→ `06-Blog-博客`（`Ideas-选题` 或 `Drafts-草稿`）
   - 生活（水电、健康、消费、证件等）→ `04-Life-生活`
   - **待办/行动项**（有明确动作、尤其是带截止时间的）：不要在 Vault 里建待办笔记——
     运行 `ru41 --config /etc/ru41/config.toml --db /data/state.db todo add --title "<标题>"`
     （能解析出时间就加 `--due "<时间>"`）转入待办数据库，QQ `/待办` 可查可提醒。
     原文若还有参考价值，归档到对应主题目录并在文末追加一行「已转待办」；
     纯一句话待办转完可直接删除 Inbox 里的原文件。
   - 无法判断的保留在 `00-Inbox-收件箱` 并在标题前缀 `[待分类]`
4. 移动文件时保持原始内容完整：不删减、不改写事实内容，只允许补充 frontmatter（如 `created`、`tags`、`aliases`）和文末追加一行归档说明。
5. 标题规范：笔记标题即文件名，去掉无意义前缀，使用清晰的中文名词短语；重命名文件后必须修复指向它的双链（`[[...]]`），用 `[[新路径|原标题]]` 保留显示名。
6. 不执行任何 git 命令（提交与推送由程序负责），不访问网络，不读写 Vault 根目录之外的文件——唯一的例外是上面第 3 条的 `ru41 todo add`（写待办数据库是授权动作）。
7. 内容指纹意识：如果文件内容与本次变更显然不符（像是被人工大幅改动过），跳过该文件并在输出中说明，让下一轮重新处理。
8. 同一主题的多条收件箱记录可以合并进一篇笔记，但合并前保留每条原文块，不丢失信息。
9. 完成后输出每个文件的处理结果：`文件 → 动作（归档至 X / 保留待分类 / 跳过原因）`。
10. `00-Inbox-收件箱/整理索引.md` 是程序自动生成的归档去向索引：不要移动、改名、修改或删除它，也不要把它当作待整理文件。
