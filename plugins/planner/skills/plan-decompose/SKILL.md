# 长期规划拆解（快照协议）

任务的文档内容已由程序内联在 prompt 里（脱敏、可能截断）。你**没有文件系统与 git 权限**，
也不需要它们：阅读快照、给出指令 JSON，落盘由程序执行。

## 背景

一份长期规划文档分两层：

- **战略层（人写的）**：目标陈述、验收标准、停止条件、里程碑标题与描述 —— 决定「做什么、为什么」
- **战术层（你写的）**：每个里程碑下的步骤序列（做什么、多久）—— 决定「怎么排进时间槽」

程序只做装箱（把步骤装进时间槽，允许跨块切分），**它不猜时长**。所以步骤必须由你给出；
缺了步骤，这一轮就排不出日程。

## 任务

对 prompt 里「待拆解的里程碑」逐个给出步骤：

1. 每个里程碑都要有 steps，`name` 与【】里的**完全一致**（不要改写、不要新增、不要漏）。
2. 每个 step 的 `minutes` 是**这一步的净时长**：一个人能独立做完这一步要多久。
   - 读一章书 ≈ 60-90 分钟
   - 读一节 ≈ 30-45 分钟
   - 写一组练习 ≈ 45-90 分钟
   - 写一个小功能 ≈ 90-180 分钟
   - 复盘/整理笔记 ≈ 20-30 分钟
   **估的是这一步，不是这个里程碑的总量。**
3. `steps` 有序，按实际执行顺序排。一个里程碑通常 3-6 步。
4. 难啃的里程碑多留时间（第一次学新概念通常比复习贵）。
5. 不要输出 prompt 里没列的里程碑。

## 边界

- 不执行任何 git 或文件操作，不访问网络。
- 不评价规划本身好不好 —— 你只负责拆步骤；「该不该做这个目标」是人的决定。
- 拿不准时长时给保守估计：总时长估高了会导致规划不可行，估低了会导致做不完。

## 输出（严格遵守）

回复**只包含一个** ```ru41-plan-decompose 代码块，内含 JSON，不要输出其它文字：

```ru41-plan-decompose
{"milestones":[
  {"name":"M1 环境与基本语法",
   "steps":[{"name":"读 Book Ch1（安装 + cargo）","minutes":60},
            {"name":"读 Book Ch3.1-3.2 变量与类型","minutes":90},
            {"name":"动手：shadowing / if-match 练习","minutes":90}]}
]}
```
