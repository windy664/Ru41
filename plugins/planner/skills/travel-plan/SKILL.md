# 出行规划助手

## 结构（vault 挂载在 /vault）

- 根目录 `/vault/04-Life-生活/Travel-出行/`；`行程索引.md` 是命名规则与全部行程总表的权威来源，动手前先读它。
- 月份文件夹 `YYYY年M月/`（如 `2026年11月`），笔记 `YYYY-MM-DD-<目的地>出行规划.md`（行动版：时间表、路线、必做清单）。
- 可选配套：`-细节与档案.md`（交通细则、比价、来源链接）与 `YYYY-MM-DD-配图/`（正文用标准 Markdown 相对路径引用，改名不丢图）。
- frontmatter 约定：`title`、`aliases`（常见口语叫法，如「11.14香港行程」）、`tags: [travel/<目的地>, planning]`、`status`（draft/final）、`created`/`updated`。

## 模糊匹配（引用已有行程时必做）

用户说「香港那个行程」「上次去深圳的计划」这类模糊指代时：

1. `ls /vault/04-Life-生活/Travel-出行/` 列月份文件夹，再逐月列笔记；
2. `rg -i "<关键词>" /vault/04-Life-生活/Travel-出行` 按目的地、frontmatter aliases、日期多路匹配；
3. 唯一命中 → 直接读/改那篇；多个命中 → 列候选让用户挑；零命中 → 明说没找到，问用户是新建还是补线索。**绝不凭猜测新建同名笔记覆盖。**

## 新建 / 更新行程

1. 先按上面的模糊匹配确认同目的地、近日期的笔记不存在；
2. 按索引里的命名规则建笔记：日期取出发日；先写行动版，细节资料多再拆 `-细节与档案.md`；
3. aliases 里记下用户的口语叫法，方便下次模糊匹配；
4. 更新 `行程索引.md` 的月份表格（日期 / 行程 / 链接 / 状态）；
5. 时间、车次、价格等事实查证后写入并注明来源，不编造。

## 纪律

- 改已有行程笔记时保留用户手写内容，只增改相关段落；
- vault 只读挂载时给出完整文本让用户自行落盘，不要写一半。
