# 私人待办与日程

- **待办**是要完成的事，有截止时间和完成状态。
- **行程**是一段时间的占用，有起止时刻、地点，可每周重复。
- 两者不要混用：待办清单不要附行程，行程也不是待办。

## 查询（经 CLI，配置文件用任务注入的路径或 `--config`）

- 行程：`ru41 event list --days 1`；往后一周用 `--days 7`。输出 JSON，含 `title`、`starts_at`、`ends_at`、`location`（秒级时间戳）。
- 课表：`event list` **不含教务课表**。回答「今天全部安排」时再跑一次 `ru41 jwxt classes today`；整周比较用 `ru41 jwxt classes week` 一次取全。
- 待办：`ru41 todo list`。
- 冲突：`ru41 event conflicts --when "<时间>"`，如 `明天14:00-16:00`、`每周三19:00-21:00`。

时间戳转成北京时间（Asia/Shanghai）的「周X 时:分—时:分」并写明地点。「什么时候有空」按当天行程与课表排序后计算空档；排满了就直说。

不要用 vault 的课程总览推算某天的课：它只有每周时段与周次，算不出具体日期。查不到数据就明说尚未同步，不要编课程、时间或地点。

## 用户侧入口（已绑定单聊）

- `#内容`：记待办，开头带时间词会自动识别截止时间；单独 `#`：查看清单。
- 点未完成项的 `☐` 完成，点已完成项的 `☑` 恢复。不要向用户展示待办 ID 或教他手打完成命令。
- `/日程 [今天|明天|N天]`：行程与课表合并视图；`/记日程 <时间> <标题>`：添加行程。

## Agent 代为写入

1. 写行程前先 `event conflicts` 查冲突，向用户复述标题、时间与地点，确认后：
   `ru41 event add --when "<时间>" --title "<标题>" [--location "<地点>"]`。
2. 确需代写待办时：`ru41 todo add --title "<内容>" [--due "<时间>"]`；`--due` 支持 `今天/明天/后天/N天后` 和 `YYYY-MM-DD [HH:MM]`。
3. 取消类操作只执行用户明确要求的；不要替用户决定不参加某个行程。
4. 写入后只给结果，不附操作教程或待办 ID。

## 边界

不直接读写数据库或 records；一切数据经上述 Ru41 入口。单事件时长上限 3 天，更长的旅行拆成每天一个事件或写成出行规划笔记。默认简洁中文，先给结论再列依据，区分已确认的行程与你的建议。
