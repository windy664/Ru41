# Obsidian 收件箱整理（快照协议）

整理任务的文件正文已由程序内联在 prompt 里（脱敏、可能截断）。你**没有文件系统与 git 权限**，
也不需要它们：阅读快照、给出指令 JSON，落盘由程序执行。

## 任务

对 prompt 中每个文件判断处理方式：

1. 归档：给出 `moves`（from → to）。目录映射：
   - 知识 → `03-Knowledge-知识`
   - 项目 → `02-Projects-项目`
   - 机会（竞赛/科研/实习/奖学金等）→ `05-Opportunities-机会` 对应子目录
   - 课程 → `01-Courses-课程` 对应学期目录
   - 文章（博客选题/素材）→ `06-Blog-博客`（`Ideas-选题` 或 `Drafts-草稿`）
   - 生活（水电、健康、消费、证件等）→ `04-Life-生活`
   - 无法判断的保留在 `00-Inbox-收件箱`，目标文件名前缀 `[待分类]`
2. 待办：快照里有明确行动项（尤其带截止时间）→ 输出 `todos`（title + due，YYYY-MM-DD）。
   不要试图调用 `ru41 todo add`——宿主会代为入库。
3. 删除：只有「纯一句话待办」（全文 ≤2 行、无其他信息）且待办已进 `todos` 的文件
   允许列入 `deletes`。其余任何文件只移动不删除——设计文档、清单、草稿即使看似过时也只能归档。
4. 跳过：非文本、读取失败（prompt 已标注）、或无法判断归属的 → `skipped`，保持原位。

## 规则

- 只依据快照内容判断，不要臆造文件系统状态；快照是唯一信息源。
- `from`/`to`/`deletes` 都是 Vault 内相对路径：不以 `/` 开头、不含 `..`。
- 标题即文件名：去掉无意义前缀，用清晰的中文名词短语。双链修复由人工与后续检索消化，
  不需要你在指令里表达。
- 同一主题的多条收件箱记录可以合并进一篇目标笔记（from 仍按原文件各给一条 move），
  合并不丢失信息。
- `00-Inbox-收件箱/整理索引.md` 是程序自动生成的，不要移动、删除或把它当作待整理文件。
- 不执行任何 git 或文件操作，不访问网络。

## 输出（严格遵守）

回复**只包含一个** ```ru41-organize 代码块，内含 JSON，不要输出其它文字：

```ru41-organize
{"moves":[{"from":"Inbox/a.md","to":"01-Courses-课程/2026-Fall-大一上/a.md"}],
 "deletes":["Inbox/一句话待办.md"],
 "todos":[{"title":"交实验报告","due":"2026-11-08"}],
 "skipped":["Inbox/img.png"]}
```
