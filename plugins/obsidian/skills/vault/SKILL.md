# Vault 知识库框架

`/vault` 是用户的 Obsidian 知识库，双向 git 同步——写完即完成，不要做 git 操作，同步守护进程会自动提交推送。

## 目录框架

- `00-Inbox-收件箱/`：临时收集区，每 7 天自动整理。用户明说「先放着」才往里写。
- `01-Courses-课程/<学期>/<课程>/`：课程材料。当前学期 `2026-Fall-大一上`，已有课程目录：高等数学I(理)、网络空间安全导论、大学英语I（综合基础）、军事理论、思想道德与法治、国家安全教育、形势与政策 I、"五史"教育、程序设计基础、办公软件、大学体育I、体能训练 I、职业生涯规划。课堂内容归对应课程：笔记写进 `课堂笔记.md`，作业写进对应作业文件，图片/文件进 `<课程>/attachments/`。
- `02-Projects-项目/`：`Active-进行中/` 与 `Archived-归档/` 分区，项目各自一个目录。
- `03-Knowledge-知识/`：通用知识（Computer-Science-计算机科学、Mathematics-数学、School-学校 等）。
- `04-Life-生活/`：`Travel-出行/`（行程规划）等。待办不在 vault 里——待办只认数据库，QQ 是唯一界面。
- `05-Opportunities-机会/`：竞赛（`Competitions-竞赛/`）、实习、人才政策等机会信息。
- `06-Blog-博客/`：`Drafts-草稿/` 与 `Published-已发布/<YYYY-MM>/`。

## 规矩

- 附件存到所属主题的 `attachments/` 子目录，笔记里用相对路径引用（如 `attachments/2026-11-06-xxx.jpg`）。
- 优先归进已有目录；确实没有合适的才建新目录，拿不准就放 Inbox 并在文内注明。
- 命名与邻近文件风格保持一致（中文名、日期前缀 `YYYY-MM-DD-` 都常见）。
- `Published-已发布/` 的内容会公开到 GitHub Pages：写入前必须脱敏——校名、人名、学号、电话、密码等一律不写；用户让发草稿区的东西不要挪进已发布。
- vault 里有敏感信息（密码、证件号）。读到的敏感内容只用于当次任务，不要复制到别的文件。
