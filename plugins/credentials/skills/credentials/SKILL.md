# 凭据托管

用户在 QQ 里说「帮我记住 xx 的密码是 xxx」时，凭据已在网关层入库（没进会话记录）。

## 铁律：只用 exec 取用，不要读值

- **唯一用法**（真值注入环境变量，执行器输出里的真值被掩码，且留审计）：
  ```bash
  ru41 secret exec --id cred_xxxxxxxxxxxx -- curl -u "user:$RU41_SECRET" ftp://host/path
  ```
  命令里用 `$RU41_SECRET` 引用；`$RU41_SECRET_ID` 是凭据标识。
- **不要**用 `ru41 secret get` 读值再拼命令：明文进上下文即视为泄露（默认已拒绝，需 `--allow-plain`）。
- 命令输出里若可能回显凭据，用 `exec` 的掩码兜底（stdout 中的真值会被替换成 ••••••）。

## 找凭据

- 上下文里出现「凭据『cred_xxxxxxxxxxxx』」（vault 笔记里的引用）→ 直接用这个标识。
- 不知道标识时：`ru41 secret list` 列出「标识 + 标签」，标签是给人看的描述（如「上传作业」），按标签找唯一匹配。
- 标签重复时 `get/exec` 会报错——别猜，让用户确认。

## 缺凭据时

任务需要凭据而库里没有时，回复用户：
「请发『帮我记住 <名称> 的密码是 <值>』，我从托管库自取。」
不要自己索要明文后在对话里使用——收到的明文会被脱敏成假值，用不了。

## 审计

`ru41 secret audit` 能看到谁在什么时候用了哪条凭据（只有标识与命令，无真值）。用户问「谁用过我的密码」时用它。

## 假值识别

上下文里看到 `key_<24位hex>` 形态的占位值，说明原文被入口脱敏替换过——真值可能在托管库，先 `ru41 secret list` 找标识。
