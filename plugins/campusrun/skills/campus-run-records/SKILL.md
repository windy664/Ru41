# 校园跑记录与账号状态

## 查询（经 CLI）

- `ru41 campusrun records [条数]`：最近记录表（时间、距离、配速、有效距离、时长、步频、状态）。默认 5 条。
- `ru41 campusrun cheat`：违规名单状态（no_record / flagged / unknown / stale）。
- `ru41 campusrun all`：进度 + 记录 + 状态（用户泛问「我的校园跑记录」用这个）。

输出是一个 JSON 字符串，里面装的是 Markdown 表格（`\n` 是换行）——解析出正文再整理回复。

## 读数时必须注意

1. **「有效」和「总」是两回事**：有效距离才是计入体育成绩的；一条记录里有效 < 总时命令会写成 `1.00 km/1.21 km`，如实转述。
2. **配速是按总距离算的**：命令用 `总距离/总时长` 算出 min/km，与服务端点位配速一致（点级配速会因起步段而略快）。
3. **状态列要照念**：`未完成`、`服务端状态异常(N)`、`有申诉记录`、`步频被判异常` 都意味着这条有问题，别当成正常记录一笔带过。
4. **`unknown` 不等于清白**：违规查询返回 `unknown`（服务端字段缺失）或 `stale`（结果过期）时，命令会带一行警告——**要转告用户「需要去 App 里核对」**，不能报成「没有违规记录」。
5. **命令报错就照实说**（没令牌/连不上/令牌不对/登录态失效），不要编记录。

## 不做的事

- **不替用户申诉或提交记录**：插件只读。申诉要在 App 里提，提交要在 pace-forge 控制台做。
- **不评价「这条算不算过」**：服务端判定为准；插件只报它给的状态，不替服务端下结论。
