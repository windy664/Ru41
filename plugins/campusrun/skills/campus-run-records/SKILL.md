# 校园跑记录与账号状态

## 查询（经 CLI）

- `ru41 campusrun records [条数]`：最近记录表（时间、距离、配速、有效距离、时长、步频、状态）。默认 5 条。
- `ru41 campusrun cheat`：违规名单状态（no_record / flagged / unknown / stale）。
- `ru41 campusrun all`：进度 + 记录 + 状态（用户泛问「我的校园跑记录」用这个）。

输出是一个 JSON 字符串，里面装的是 Markdown 表格（`\n` 是换行）——解析出正文再整理回复。

## 读数时必须注意

1. **「有效」和「总」是两回事**：有效距离才是计入体育成绩的；一条记录里有效 < 总时命令会写成 `1.00 km/1.21 km`，如实转述。
2. **配速是按总距离算的**：命令用 `总距离/总时长` 算出 min/km，与服务端点位配速一致（点级配速会因起步段而略快）。
3. **状态列要照念**：`未完成`、`服务端状态码 N（接口未说明含义）`、`有申诉记录(appealStatus=N)`、`步频状态异常(stepFreqStatus=N)` 都意味着这条有问题，别当成正常记录一笔带过。但**别替服务端解释状态码的含义**——接口没写、控制台也不读这个字段，只能照念并建议去 App 里核对。
4. **`unknown` 不等于清白**：违规查询返回 `unknown`（服务端字段缺失）或 `stale`（结果过期）时，命令会带一行警告——**要转告用户「需要去 App 里核对」**，不能报成「没有违规记录」。
5. **「全校通报榜 N 人」跟你无关**：服务端原始响应里 `self`（你的违规信息，null = 干净）和 `list`（全校通报榜，别人）是两回事。命令输出里「全校违规通报榜：N 人（是你的无关）」这一行**不能**被说成「你被通报了 N 次」；你自己的状态看「你的违规记录」那一行。
6. **命令报错就照实说**（没令牌/连不上/令牌不对/登录态失效），不要编记录。

## 跑一次（用户明确要求时）

- `ru41 campusrun plan --laps 3`：预演（生成轨迹 + 八类自检，**不提交**），会给出里程、
  配速、步频、必过点命中、工具自检结论，外加**上次提交的逐条规则判定**。
  圈数自动换算（1 圈 = 400 m，3 圈 = 1.2 km）。
  **能不能跑由工具自己的 preflight 说了算**，插件不自己判；没过就把工具给的原因原样念出来。
- 提交是**两步**：`ru41 campusrun submit` 只登记待确认（给口令），用户明确同意后才
  `ru41 campusrun confirm <口令>`（**别用 `run`**：宿主会把它当成 tracker 的长驻任务抢走）。
  **没有用户明确同意，不要走到 confirm。**
- **什么时候跑由你从话里读**：用户说「半小时前那次」就加 `--ago 30`，说「昨天九点那次」就加
  `--at 09:00 --days 1`，没提就不带时间参数（= 刚跑完）。配置里没有这一项，别去配置里找。

## 不做的事

- **不替用户申诉**：申诉要在 App 里提。
- **不评价「这条算不算过」**：服务端判定为准；插件只报它给的状态，不替服务端下结论。
- **不主动提交跑步记录**：提交要用户明确要求，且插件默认不开提交（allow_submit）。
