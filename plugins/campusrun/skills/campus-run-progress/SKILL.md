# 校园跑进度

## 查询（经 CLI）

- `ru41 campusrun status`：学期进度——学期名、有效里程/总里程、有效次数、学期目标次数、目标距离、剩余天数、是否达标。
- `ru41 campusrun all`：进度 + 最近记录 + 账号风控状态（一次出全部，用户问「我的校园跑怎么样」用这个）。
- `ru41 campusrun records [条数]`：最近若干条记录。
- `ru41 campusrun cheat`：违规名单状态。

输出是一个 JSON 字符串，里面装的是 Markdown（`\n` 是换行）——解析出正文再整理回复，别把转义符原样贴给用户。

## 读数时必须注意

1. **有效里程才算成绩**：命令会同时给出「有效里程」与「共 X km」，总里程含无效的那部分，回答时要说清用的是哪个。
2. **目标是「次数」不是公里数**：学期目标以 `目标次数` 为准（当前是 1 次），`目标距离` 是规则要求的**单次最小里程**，别把两者混成「还差几公里」。
3. **别用 pace-forge 自带 CLI 的那一行**：它的 `semester` 输出把学期目标打成「0.0km / 0 次」（读错字段），以 `ru41 campusrun status` 为准。
4. **命令报错就照实说**：没令牌、连不上控制台、令牌不对、登录态失效，命令都会直接报错——把原因转述给用户（如「pace-forge 控制台没连通，先确认容器在跑」），**不要编一个进度数字**。

## 不做的事

- **不替用户提交跑步记录**：本插件只读。用户要「帮我跑一次」时，说明当前只支持查进度；如需提交要在 pace-forge 控制台手动做，并提醒：提交要在有效时段内、记分跑必须过全部打卡点且在校区内围栏、提交后 600 秒内不能再发跑步请求。
- **不预测「今天能不能过」**：有效时段、打卡点、围栏这些规则随时可能变，插件 P0 不查这些，要问就让他去控制台看。
