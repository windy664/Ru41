# Agent 底座契约

## 当前边界

Ru41 的业务宿主使用 Rust。Codex 是首个已接入底座；后续可添加其他 CLI Agent、独立 Agent 服务或自建运行时。底座与底座内部选择的模型分别记录。

`AgentBackend` 提供：

- `descriptor()`：稳定后端 ID、模型配置、支持的执行契约、适配器是否支持续接。
- `run(AgentRequest)`：接收提示、运行目录和契约，异步返回统一结果与可选会话 ID。
- 丢弃执行 future 时停止拥有的工作；进程型实现负责子进程清理，远程服务型实现必须说明服务端取消限制。

`BackendRegistry` 只在启动时显式注册实现，拒绝重复 ID；不是动态插件加载器。CLI 当前仅注册 Codex。任务写入后绑定后端，重试和租约接管不能悄悄切换底座。

## analysis_v1

当前唯一执行契约：根据传入材料进行分析，结果为一个仅含非空 `summary` 的对象。宿主验证 JSON 结构和长度后保存。该契约不提供真实 Vault 写入、作业提交、公开发布等外部动作。

Codex 适配器要求进程成功退出、收到 `turn.completed`、没有失败事件、最终 JSON 合法且通过业务校验。结果和尝试状态在同一数据库事务中保存。

`supports_resume=false` 表示当前适配器尚未实现会话续接，不代表 Codex 产品没有此能力。当前重试会创建新会话。`session_id` 只作为底座内部标识记录，不在不同底座间传递。

## 增加真实底座

1. 在 `adapters` 实现 `AgentBackend`，处理自身的认证、连接、原生事件、输出格式和取消。
2. 声明实际满足的契约；不同底座不得仅返回文本就声称满足工具执行或审核能力。
3. 将原生结果映射为 `AgentOutput`，保留适配器日志和本地运行目录。
4. 在应用装配处注册，扩展该底座的配置入口。
5. 使用公共契约测试验证超时、取消、输出错误、失败恢复、身份记录和任务隔离，再进行真实接入验证。

SQLite 和 Worker 不导入 Codex 协议类型。新增底座不修改任务去重、租约和持久化流程；必要的新业务契约作为明确的 schema/状态迁移引入。

## 后续扩展

工具调用、附件、流式事件、错误分类、会话恢复和预算报告尚未统一。需要第二种真实底座或相应业务时，再为这些能力定义可测试契约。不同底座的沙箱、工具权限和会话语义不应被伪装成完全相同。

不会默认自动降级到其他底座：这可能改变数据发送位置、权限、行为和成本。跨底座重新执行必须是显式的新任务或后续专门设计的迁移流程。

## 与功能模块的关系

- 底座适配器决定任务由哪套 Agent 运行时执行。
- 功能流程决定整理笔记、追踪论文等业务如何处理。
- 消息适配器决定用户从哪个平台交办与接收结果。

这三个边界独立演进；无需先实现动态插件系统才能接入第二个 Agent 底座。
