# 自动学习规划：能做到哪一步，以及它和 AGI 的关系

> 起因：长期规划如果能全自动，**是不是就接近 AGI 了？**
> 这篇给出精确回答，并把「背书知识点」这一层的落地方案定下来（**FSRS v7，官方 Rust 实现，本机已跑通真实模拟**）。

---

## 0. 一句话回答

**直觉方向对，但位置要下移。**

"全自动学习规划"其实是 **4 个子问题**的叠加，其中**只有最后一个是 AGI 那一层**，
前三个早就被成熟算法和产品吃掉了：

| # | 子问题 | 现状 | 需要 AGI 吗 |
|---|---|---|---|
| ① | **知识点什么时候该复习** | **FSRS v7，已解决**（DSR 模型 + 34 参数 + 强化学习优化 + 基准测试） | ❌ 纯数学 |
| ② | **从材料生成卡片** | LLM 已解决（engram 的 MCP `create_notes` 就是干这个） | ❌ |
| ③ | **塞进日程的空隙** | 已解决（空闲计算，确定性代码） | ❌ |
| ④ | **决定学什么、值不值得、何时转向** | **开放问题** | ✅ **AGI 在这里** |

**所以**：坏消息是你最想要"全自动"的那部分恰好最难；好消息是 **Ru41 不需要 AGI 就能做出一个非常能打的自动学习系统**——因为 90% 的价值在 ①②③。

## 1. 为什么 FSRS 能全自动，而"全自动长期规划"没有

**关键不在"用了机器学习"，在于能不能测量效果。**

**FSRS 成功的原因是把状态空间压到了最小：**

- 每张卡只有 3 个状态变量：长期稳定性 `S_long`、短期稳定性 `S_short`、难度 `D ∈ [1,10]`
- 效果**可测量**：复习成功率 / log loss
- 有基准测试（`srs-benchmark`，时间序列切分验证），参数可个性化优化

**长期规划的状态空间则爆炸：**

```
6 个目标 × 各自进度 × 精力 × 疲劳 × 课表 × 心情 × 外部锚点 × 历史欠账
```

效果**不可测量**——"这周学了 Rust 是否让我更好了"没法量化。
**不能测量 ⇒ 不能优化 ⇒ 只能靠人。**

> **这是 AGI 之前和之后的分界线：不是"智能"，是"可测量性"。**
> 也解释了 Reclaim 2.0 为什么**刻意不做全自动**：它不敢自动的是 ④，不是 ①。

## 2. ① 层怎么落地：FSRS v7

### 2.1 现成的东西（不是自己造）

| 项目 | 说明 |
|---|---|
| [`fsrs` crate v7.0.0](https://github.com/open-spaced-repetition/fsrs-rs) | **官方 Rust 实现**，edition 2024，BSD-3-Clause，含 `FSRS::next_states` 与 `Optimizer` |
| FSRS-7 | 状态 `(S_long, S_short, D)`，**34 个参数**（v6 是 21 个），联合优化 |
| **小数间隔** | FSRS-7 的 `interval` 是 `f64` 天数，**支持亚天** → 10-20 分钟的课间碎片能被正确建模（FSRS-6 做不到） |
| `srs-benchmark` | 官方基准测试，仍在活跃维护 |
| `engram` | 自托管 SRS 服务，**自带 MCP server**（`create_notes` 批量出卡、`get_due_cards` 拉到期卡） |
| `true-recall` | **Obsidian 原生**间隔重复插件：AI 生成闪卡 + FSRS v6 + 留存分析 |

**对 Ru41 最重要的两点**：

1. **FSRS-7 的小数间隔** —— Ru41 的碎片池全是 10-20 分钟的课间缝，只有 FSRS-7 能正确建模
2. **`Optimizer`** —— 用你自己的复习历史个性化参数（需要几百次历史才准，前几周用默认参数）

**环境已实测**：本机 `crates.io` 的搜索 API 返回 403，但 `index.crates.io` 与 `static.crates.io` **均返回 200**，
`cargo add fsrs` 正常工作，`fsrs v7.0.0` 已在本机编译通过。

### 2.2 卡片从哪来

Ru41 已经有 `lecture` 插件（课堂笔记）+ `obsidian` 插件（Vault）——**课堂笔记本身就是卡片的原料**：

```
课堂语音 → lecture 插件 → Vault 笔记 → LLM 抽问答题对 → 卡片 → FSRS 调度 → 碎片复习
```

这正是 `engram` 用 MCP 做的事（`create_notes` 从材料批量出卡），但 Ru41 已经有 Vault 和 agent，不需要额外服务。

### 2.3 复习提醒怎么落

复用现有的 `EventItem` + `remind_at` 循环：到期卡写成事件（`source.channel = "fsrs"`），走已有的提醒链路。

## 3. 真实模拟跑出来的数

模拟代码：[`scripts/fsrs-probe/`](../scripts/fsrs-probe/)（`cargo run --release`，本机已跑通，用的是真 FSRS v7）。

**模拟口径（对齐 Ru41 实测课表）**：300 张卡 / 16 周 / 每张 10 秒 / 目标留存 90%；
整块每周引入 20 张新卡；碎片预算 = 每天 13 分钟（= 90min/周 ÷ 7）。

### 3.1 碎片池根本不是瓶颈

| 每天碎片 | 学期末掌握（300 张卡） |
|---|---|
| 2 分钟 | 299 张 |
| 3 分钟 | 300 张 |
| 5 / 8 / 13 分钟 | 300 张 |

> **每天只要 2 分钟，就能把 300 个知识点维持在 90% 留存。你的碎片池（13 分钟/天）是 6.5 倍冗余。**

### 3.2 真正稀缺的是"整块引入新卡的速度"

| 每周新卡（用整块学） | 学期末掌握 |
|---|---|
| 10 张 | 159 张 |
| **20 张** | **299 张** |
| 30 张 | 300 张 |

> 每周引入 10 张时只掌握 159 张 —— **不是因为碎片不够（碎片有 8 倍冗余），而是因为只学了 160 张。**
> **背书知识点的瓶颈是整块，不是碎片。**

### 3.3 留存率的代价（碎片完全撑得住）

| 目标留存 | 总复习次数 | 每天需碎片 | 积压峰值 |
|---|---|---|---|
| 85% | 492 | **0.7 分钟** | 23 |
| 90% | 928 | **1.4 分钟** | 30 |
| 95% | 1887 | **2.8 分钟** | 36 |
| 98% | 3620 | **5.4 分钟** | 70 |

> **碎片池 13 分钟/天能撑到 98% 留存。** 留存率不是被碎片限制的——想保多少保多少。

### 3.4 这修正了我上一轮的一个结论

[portfolio.md §3](portfolio.md) 里我写过："碎片池只有 90 分钟/周，所以『每天 20 分钟 × 5 天』装不下，背书必须降到 15 分钟 × 5 天"。

**那个判断错在假设了"均匀复习"。** 均匀复习确实装不下（150 分钟 > 90 分钟），
但 **FSRS 下不需要均匀**——它会自动挑最该复习的那批，每天 2 分钟就够。

**结论改写**：碎片池对"背书"这个用途来说是**绰绰有余的**，
真正要省的是**整块**（要拿来学新知识、要拿来给 Rust/四级/高数）。

### 3.5 Naive vs FSRS：差别几乎看不见——但这不是 FSRS 的问题

两种策略（按创建顺序 vs 按最接近遗忘优先）在所有预算下结果几乎一样（299 vs 300 张）。
**原因不是 FSRS 没用，而是预算从来不是约束**（§3.1）。

FSRS 的价值要等预算真的吃紧才显现。而 Ru41 的碎片池不会吃紧——**所以对 Ru41 来说，
选 FSRS 的理由不是"省时间"，而是下面这个。**

## 4. FSRS 真正的价值：把记忆层和目标层连起来

**退步信号**。FSRS 每个知识点都带 `D`（难度）和 lapse 计数（复习时按 Again 的次数）。
这两个信号能回答："**我在哪些知识点上退步了？**"

```
某个知识点 D 持续升高 / 反复 Again
        ↓
它不是「碎片再刷一遍」能解决的（碎片只维持记忆，不重建理解）
        ↓
它需要「整块时间重新学一遍」
        ↓
→ 进入整块时间的重新分配候选池
```

**这是把可测量的记忆层（①）和不可测量的目标层（④）连起来的方式**——
而且连接方式是**确定性规则**（D 阈值 + lapse 计数），不是 LLM 拍脑袋。

这跟 Ru41 既有哲学一致：**能规则化的判断都落成代码，agent 只做相关性和文案。**

## 5. 三层分工（Ru41 的最终形态）

| 层 | 谁做 | 是不是 AI | 自动程度 |
|---|---|---|---|
| **记忆调度**（何时复习某张卡） | **FSRS v7 算法** | ❌ 纯数学 | **全自动** |
| **卡片生成**（从课堂笔记出题） | LLM | ✅ 但不需要 AGI | 全自动（agent 任务） |
| **排期**（放哪个空隙、哪一天） | 确定性代码 | ❌ | 全自动（+ 人的审批） |
| **目标决策**（学什么、值不值得、何时转向） | **人** | ✅ AGI 那一层 | **半自动**（系统只问） |

对照 [portfolio.md](portfolio.md) 的三层（硬锚定 / 跟课 / 日常），「背书知识点」这一条
从"需要人分配额度"**降级为"碎片型全自动"**——因为它的复习时机有数学模型，不需要人拍板。

## 6. 诚实的保留

1. **模拟的评分是"随机猜"**（用 FSRS 的 retrievability 决定记得/忘记）。
   真人会努力想，所以真实留存会更好、`D` 分布也更温和。
   §3 里"退步信号 245/300 张"是这个随机评分的产物，**不是真实预期**。
2. **FSRS 的个性化参数需要几百次复习历史**才准，`Optimizer` 前期帮不上忙，用默认参数。
3. **300 张卡是我估的量级**，不是你的真实知识点数。要更准就得先把卡片生成跑起来，看实际产出多少张。
4. 模拟**没有建模"学新知识"本身要花多久**——它假设每周 20 张是整块时间能吃下的。
   真实情况要等 `lecture` 插件的笔记跑通后才知道。

## 7. 下一步（按性价比排序）

| 步骤 | 做什么 | 为什么先做这个 |
|---|---|---|
| 1 | 手工从**一篇课堂笔记**生成 20 张卡，用 Anki 跑一周 | 验证"卡片生成 + FSRS"这条链真的通，零代码 |
| 2 | 看自己每天实际花多久在碎片复习 | 验证 §3.1 的"2 分钟就够"在真人身上成不成立 |
| 3 | 把 FSRS 调度接进 Ru41（`fsrs` crate + 现有 `EventItem` 提醒） | 有真实数据后再自动化 |
| 4 | 接退步信号 → 驱动整块时间重分配 | 这是 §4 的核心，也是 Ru41 最有差异化的一步 |

**不建议**先做"全自动长期目标规划"——那是 ④，是 AGI 那一层，而且 §3.2 已经证明：
**你要的自动化里，瓶颈根本不在时间。**
