# 证据驱动的规划刷新（推翻前一版方案）

> **本文推翻了我自己前几轮方案的核心前提。**
> 触发点：用户指出"市面上的 AI 规划学习空洞泛滥，真正���规划是**通过与 AI 对话完成问卷**，
> AI 先问你有什么基础、手头有什么材料，**并结合你的知识库得到实际情况**"。
>
> 我按这个方向查了生产知识库与 Ru41 数据库，结果：**我之前给的规划（"学 Rust 基础"）是完全错的。**

---

## 1. 我之前做错了什么

| | 我之前做的 | 为什么空洞 |
|---|---|---|
| 规划来源 | AI 从零生成一套目标/里程碑/时间块 | 没看过你的实际情况，等于给任意一个人同一份计划 |
| 问你的方式 | 没问（或问"你有什么基础"这种通用问题） | 通用问题只能得到通用答案 |
| 目标选择 | 凭我的想象挑了"学 Rust 基础" | **你早就在写 Rust 生产系统了**（Ru41 就是） |
| 文档格式 | 我自己发明 `frontmatter + steps` | 你早有一套（表格：目标/现状证据/状态/下一动作） |
| 规划目录 | 我猜 `08-Planning-规划/Plans-计划/` | 实际是 `04-Life-生活/Planning-规划/Plans-计划/` |

**根因**：我把"规划"理解成了**资源分配**（谁占哪个时间块），而规划的本质是**基于你的实际处境做取舍**。
前者是排程，后者是判断——排程可以让机器做，判断必须先知道你是谁。

## 2. 正确的分工：AI 查证，人决策

```
① 采集证据   知识库 + Ru41 数据库 + git + 竞赛/成绩 + 课程系统
      ↓
② 判定状态   对照你已有的每一格，标 ✅ 已完成 / ⛔ 停滞 / 🟡 进行中 / ⬜ 未开始
      ↓
③ 提问       ★ 只问「证据查不到」的 ★（动机、感受、取舍变更、机器查不到的事实）
      ↓
④ 写回账本   状态 + 新证据 + 下一动作，回到你的规划文档
      ↓
⑤ 排期       最后一步：把「下一动作」铺进课表空隙（服从你已定的取舍）
```

**关键在 ③**：AI 能查的绝不问人。你自己的文档已经把这条写死了——

> "15 个复选框只勾了 2 个，但同期实际产出 41 篇博客、126 个项目、57 篇数学/编程笔记
> ——**问题不是没执行，是执行结果没回写**。"

所以 AI 在规划里的首要职责是**回写账本**，其次才是提问。提问是补漏，不是入口。

## 5. 这次查出来的一个「路径错位」（不是"停滞"，是"走偏了"）

**英语**：你在用 YouTube 精听预习单推进（泛听精读，CET-6/B2 水平）；
但 IELTS 首考要的是**应试技能**——题型套路、限时训练、写作评分标准、口语题库。

> 这两件事不是一回事。**泛听精读不会自动迁移到雅思应试。**
> 你的文档写"IELTS 首考未发生 / 6.5→7.0"，但没写"这 70 天练的是另一条路径"。
> **这才是需要你拍板的点：是不是有意把雅思押到 2027 年才启动？**

这是 AI 基于证据才能发现的问题——只看"雅思笔记 0 篇"会误判成"英语停了"。

## 6. 针对性问卷（每一题都挂在证据上）

> 以下 6 题都可以由 AI 查证的，**AI 不该问你**；这些是只有人能回答的。

1. **这周的产出模式**：11-14 之后 Vault 新增全是课程笔记/作业，博客 0、数学笔记 0、编程笔记 0、CTF 文件 0。
   你是**主动切到期末复习模式**（那这是一次计划内切换，账本按新模式记），
   还是**被课程作业占满了**（那英语/CTF 这学期的窗口就真的关上了）？

2. **CTF 校内赛的具体日期**是哪天？我按它倒排这周的空闲——它是你自己说的"本学期最后一个可补的窗口"，
   但 Vault 里没有任何 CTF 痕迹，我不知道它还开不开着。

3. **Academy 的 GOSIM 补充材料有回复吗？**（11-05 前提交，文档写"暂无回复，盯邮件"；
   这个我查不到，只能问。）

4. **四门课的期末考试日期**分别定了吗？（高数 / 线代 / 网络空间安全导论 / 计算机专业导论）
   定了才能算"最后 6 周还剩多少有效复习时间"。

5. **英语这条**：YouTube 精听这条线你在继续跑，同时 IELTS 应试线完全没启动。
   这是有意的（押到 2027 年春）还是被英语断在了泛听上？
   ——**如果是后者，剩下 6 周正是补应试基础的时间窗**（题型认知 + 写作模板 + 限时套题）。

6. **PR 合并率 2/14**：你自己诊断过"合并率偏低说明还差在被 review 的质量"。
   这 6 周要不要把它当成本学期的一个动作？（现在它排在"其余一律不加新坑"之外，
   但它同时也是三轨策略里最强的一条证据。）

## 7. 新架构：AI 在规划里的位置

| 能力 | Ru41 现状 | 复用方式 |
|---|---|---|
| 知识库检索 | ✅ `vault-search` skill + `knowledge` 插件（向量检索） | 直接用 |
| 课堂笔记 | ✅ `lecture` 插件 | 直接用 |
| 执行轨迹 | ✅ `tasks` / `records` 表 | **需要新增读接口**（`tasks.prompt` 原文是金矿） |
| 课表约束 | ✅ `jwxt` 插件 | 直接用 |
| 竞赛/成绩 | ✅ `competitions` 插件 + Vault | 直接用 |
| 对话式问卷 | ⚠️ agent 天然能做，但**要有"只问查不到的"的纪律** | 新 skill：`plan-diagnose` |
| 账本写回 | ⚠️ 我前几轮写的是"step 写回"，**不是"状态写回"** | 新 skill：`plan-ledger` |

### 7.1 规划文档格式：沿用你的，不要另发明

你现在的格式（`Freshman-2026-大一计划.md`）已经是正确的形态：

```markdown
| 目标 | 现状证据 | 状态 | 下一动作 |
|------|----------|------|----------|
| 保持高 GPA | 无任何成绩记录 | ⛔ | 记一次期中/期末成绩进证据链 |
```

**AI 该做的是填这张表的第 2、4 列**，而不是造一套新的 frontmatter+steps 格式。
（我前几轮写的 `src/domain/plan.rs` 那套格式与你的实际格式不兼容，
要改成解析你的表格格式；或者更简单：**AI 只产出表格行，程序负责插入**。）

### 7.2 状态判定的依据（AI 查，不问人）

| 判定 | 依据 |
|---|---|
| ✅ 已完成 | 有**产出物**（笔记/提交/获奖/成绩），不是"打过勾" |
| 🟡 进行中 | 近 N 天有该方向的产出 |
| ⛔ 停滞 | 计划里有、但近 N 天零产出 |
| ⬜ 未开始 | 零产出且从未开始 |

> 你已经踩过这个坑："15 个复选框只勾了 2 个，但同期实际产出 41 篇博客"——
> **判定必须基于产出物，不能基于勾选状态。** AI 查产出物正好能补上这个洞。

## 8. 这条路已经通了的部分 vs 还缺的

**已通（可直接用）**：
- 知识库检索、课表、课堂笔记、竞赛记录 —— 都在
- 执行轨迹（tasks.prompt 原文）—— 数据在，只差读接口
- 问卷对话 —— agent 天然能做
- 账本表格的**行**由 AI 生成 —— 就是一次普通 agent 任务

**还缺（要新做）**：
1. `plan-diagnose` skill：**先查后问**的纪律（查得到的不问）
2. `plan-ledger` skill：把状态判定写回你的表格格式
3. tasks 表的读接口（把 prompt 原文喂给 agent 当上下文）
4. 我前几轮那套 `frontmatter + steps` 格式 —— **建议废弃**，改成你的表格格式

## 9. 与前几轮方案的关系（不是推翻，是降级）
