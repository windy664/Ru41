# 多目标编排：六个长期规划怎么分时间

> 起因：长期规划不止一个 —— 四级、华为 HICP 证书、雅思、背书知识点、高数学习规划、学 Rust，
> 每个里面还有小规划。**"这周该学哪个"这个决策很难说。**

这份文档解决的是**决策结构**问题，不是排期问题（排期见 [longterm-planning.md](../longterm-planning.md)）。

---

## 1. 为什么这个决策难，以及难在哪

难的不是"哪个更重要"——**那个问题没有可解的算法**，每次都要重新吵一遍。
难的是：**六个目标的时间形态完全不同，却挤在同一批晚上和周末里抢**。

用错的问题问，会得到错的结构：

| 问法 | 结果 |
|---|---|
| 「这周 Rust 还是四级更重要？」 | 每周重吵一次，永远没有稳定答案 |
| 「这周每个目标各分几小时？」 | 六个都分一点 → 每个都推不动 → 全都半途而废 |
| **「这周哪些目标必须做，哪些可以不做？」** | 有唯一解：先做有外部锚点的，剩下的才轮得到挑 |

**第三条才是可解的**，因为它把「排序」变成了「筛选 + 一次取舍」。

## 2. 按时间形态分层（不是按重要性）

关键重构：把目标按**时间形态**分三层，而不是按重要性排一个总榜。

| 层 | 目标 | 时间形态 | 是否需要人决策 |
|---|---|---|---|
| **L0 · 硬锚定** | 四级、雅思（考试日）<br>华为 HICP（报名/考试窗口） | **脉冲型**：截止日之前集中投入，之后归零 | ❌ 不需要——倒排自动锁定 |
| **L1 · 跟课** | 高数学习规划 | **绑定型**：跟着校历周次走，课前课后 | ❌ 不需要——绑定到相关时段 |
| **L2 · 日常** | 学 Rust、背书知识点 | **持续型**：每周都要有，靠习惯维持 | ✅ **只有这里需要决策** |

这个分层把"六选一"变成了"**两个选一个**"——决策量从 6 降到 2，而且剩下的两个都是**没有外部锚点**的（所以它们之间也没有客观答案，只能由你定）。

### L0 为什么不需要决策

脉冲型目标的投入是**被截止日倒推出来的**，不是被优先级推出来的：

```
四级考试在 12-19  →  考前 8 周需要 X 小时  →  每周 Y 小时锁定
                    ↑  不需要你决定「四级 vs Rust 谁重要」
                    ↑  需要你决定的只是「如果锁定后不够，把谁让出来」
```

Reclaim 的原话正好是这个意思：**优先级不压倒截止期**（"A P2 Task with a due date that is further out might end up scheduling after a P3 Task that is due in the next couple days"）。

### L1 为什么不需要决策

高数课在周二 10:40-12:00、周四 10:40-12:00（实测）。高数的复习天然绑在**课前/课后/当天**，
不需要跟别的目标竞争——它占的是"高数课周边"这些时段，别人也用不上。

### L2 的决策才是真决策

Rust 和背书知识点都没有外部锚点：没人规定你必须哪天学完 Rust。
所以"这周 Rust 多一点还是背书多一点"**没有客观答案**，只能由你定。
**系统的价值不是替你决定，而是把这个决定变得容易回答。**

## 3. 实测容量（这是分配的基础）

用生产真实课表算出来的一周（2026-11-23 ~ 11-29，课最全的一周）：

### 整块（≥30 分钟）

| 时段形状 | 什么时候 | 长度 | 适合 |
|---|---|---|---|
| 早晨块 | 工作日第一节 09:00/10:40 的日子 | 08:00-09:00 或 08:00-10:40 | 背诵、复习、读文献 |
| 下午块 | 无课下午 | 14:00-17:00 | 3 小时整块 |
| 晚间块 | 工作日 18:20 之后 | 18:20-23:00 | 深度工作主战场 |
| 周末 | 周六周日 | 09:00-15:00+ | 最整块的深度时间 |

**可排整块：13 块 × 2h = 26h/周**（周一晚 19:00-21:00 + 周日上午 10:00-12:00，系统按可用性+间隔推荐）

### 碎片（10-29 分钟）—— 只有 90 分钟/周

```
周一 16:50-17:00  (10min)
周三 10:20-10:40  (20min)   16:50-17:00  (10min)
周四 10:20-10:40  (20min)   15:20-15:30  (10min)   16:50-17:00  (10min)
周五 15:20-15:30  (10min)
────────────────────────────────────
合计 7 段 90 分钟，平均 13 分钟/段
```

> ⚠️ **一个硬结论**：碎片池只有 90 分钟/周，所以「背书知识点」**不能按"每天 20 分钟 × 5 天"排**（要 100 分钟，装不下）。
> 现实可行的两条路：
> - **碎片路线**：每天 15 分钟 × 5 天 = 75 分钟 ≤ 90 分钟 ✓（对应 Anki 类工具，纯记忆）
> - **早晨块路线**：用早晨块（08:00-09:00）承载"理解型"复习，碎片只留纯记忆 —— **两者分工，不要都塞碎片**
>
> 另外注意：**周二没有碎片**（10:40-12:00 和 17:00-18:20 之间 12:00-17:00 全空）。所以"每天固定 15 分钟"在周二要落到下午块上。

## 4. 学期阶段编排（这才是"决策不难"的关键）

**六个目标同时推进 = 每个都推不动。** 正确做法是分阶段，每阶段只有 1-2 个活跃目标。

> ⚠️ 下面的日期里，**考试日、报名截止、证书有效期需要你补**（我没查到 CET 官网的具体排期，2026 年 12 月的统考窗口请自行核对）。
> 框架是通用的，填上锚点就能用。

| 阶段 | 时间 | 活跃目标 | 整块分配 | 碎片 |
|---|---|---|---|---|
| **S1 基础期** | 第 12-16 周<br>(11-22 ~ 12-20) | 高数（跟课）+ **Rust** | 高数 3h + Rust 10h | 背书 75min |
| **S2 冲刺期** | 第 17-18 周<br>(12-21 ~ 01-03) | **四级**（若 12 月考）+ 高数收尾 | 四级 10h + Rust 3h | 背书 75min |
| **S3 寒假整块期** | 2027-01-04 ~ 02-28 | **雅思** 或 **HICP**（按报名窗口）<br>+ Rust 收尾 | 每周 8h，主攻一个 | 维持 |
| **S4 春季均衡期** | 2027-03 ~ 05 | 四级（二期）/ 证书 / 高数复习 | 分配给跟课型 | 背书 |

**注意 S2**：如果四级在 12 月考试，那 **12-21 之后的整块基本归四级**，Rust 只剩 3h。
这正是 `docs/plans/rust-baseline.md` 那份 13 块规划会撞上的事——**它假设整块都是 Rust 的，
一旦 L0 进来就要让位**。所以多目标不是"同时排"，是**先排 L0，L2 拿剩下的**。

## 5. 每周的额度分配（唯一一个需要你做的决策）

排期顺序是固定的，**只有最后一步需要你**：

```
1. L0 倒排     → 四级/雅思/HICP 按截止日占多少块（自动，无决策）
2. L1 绑定     → 高数绑到课程邻近时段（自动，无决策）
3. L2 剩余     → 剩下的块数 = 26h − L0 − L1
4. 你来分      → Rust : 背书 = ? : ?   ← 只有这一步
```

所以每周你要回答的问题被压缩成一句：

> **这周剩下 17 小时，Rust 10h（5 块）还是背书 10h（5 块），另一个放 7h（机动）？**

或者更省事：**默认 Rust 优先（因为它需要连续投入，碎片学不了），背书吃碎片池，不参与整块分配。**
—— 这也是一个合法的默认策略，可以直接采纳。

### 系统该做什么

系统**不排名**（排名是伪精确），只做三件事：

1. **算**：L0/L1 占了多少、剩多少、碎片池有多少
2. **报**：上周各目标的实际完成率（不是计划，是真的做了几个块）
3. **问**：把决策变成一个二选一，附上上下文

推送长这样就够：

```
本周额度
├─ 已被占用：四级 8h（考试倒排）｜高数 3h（跟课）｜背书 1.5h（碎片池）
├─ 剩余整块：13.5h ≈ 6-7 块
└─ 请选这周的 L2 重心：
   [Rust]  学 Rust 基础（还差 3 块完成学期目标）
   [背书]  背诵知识点（上周 12/15 天完成）
   [机动]  这周不推新目标，只还债
```

**回一个字就行。** 这就是"决策不难"——不是让系统替你选，而是让选择变成一个带上下文的、
三十秒能答完的问题。

## 6. 每个目标的具体排法

### L0 脉冲型：四级 / 雅思 / HICP

- **锚点**：考试日 / 报名截止（**需要你填**）
- **倒排**：从锚点往前数 N 周（经验值：四级 8 周、雅思 12 周、证书类按报名窗口）
- **每周额度**：考前最后 4 周可占 50%+ 整块；更早每周 2-3 块
- **验收**：分数 / 证书 —— 有外部标尺，不用自造
- **冲突时**：脉冲型抢占日常型（L2 让位），这是唯一允许"抢"的规则

### L1 跟课型：高数学习规划

- **锚点**：高数课表（周一/周四 10:40-12:00）+ 期末考试
- **绑定**：课前 30 分钟预习 + 课后当天复习（当天！隔天就忘）
- **小规划**：高数本身也有子目标（极限/导数/积分…），按校历周次跟随课程进度
- **验收**：课后作业 + 期末成绩

### L2 日常型：学 Rust

- **锚点**：**无** → 需要自造验收（这是 Rust 的特殊难点）
- **已有**：[rust-baseline.md](rust-baseline.md) —— 13 块学期内 + 8 周寒假，46 个测试跑通
- **验收**：5 条（能修借用错误 / 能用 `?` 组合错误流 / 能用 trait / 能判断生命周期 / 能独立写 CLI）
- **注意**：Rust 需要**连续整块**，碎片学不了 → 天然和其他 L2 目标竞争

### L2 日常型：背书知识点

- **锚点**：**无**
- **落点**：碎片池（90min/周）+ 早晨块（理解型）
- **验收**：复习覆盖率（可量化：本周复习了 N 个知识点 / 计划 M 个）
- **注意**：这是唯一能吃碎片的目标 → **建议直接定成"碎片型"，不参与整块分配**

## 7. 这套方案对 Ru41 实现意味着什么

新增一个 `goal` kind（目标 + 里程碑 + 每周节奏 + 类型标记），字段大致：

```rust
pub struct GoalItem {
    pub id: String,
    pub title: String,
    pub kind: GoalKind,        // Pulse | CourseBound | Daily | Fragment
    pub milestone: Vec<Milestone>,
    /// L0 专用：外部锚点（考试日 / 报名截止）
    pub anchor_at: Option<i64>,
    /// L1 专用：绑定的课程关键词（"高等数学"）
    pub bound_course: Option<String>,
    /// L2 专用：每周目标额度（分钟）
    pub weekly_minutes: Option<i64>,
    pub target_date: Option<i64>,
}
```

- `kind` 决定它参与哪一层排期，以及冲突时谁让谁
- L0 的锚点是**唯一需要外部数据**的字段（其余全在本地）
- 每周回顾时，系统算完 L0/L1 占用，问你 L2 怎么分

**这套东西现在还是纸面设计。** B0 阶段（手工跑）建议先手算两周：
用本文的框架，手工给四级/雅思/高数/Rust/背书各记一次"这周占多少块"，
看看这个分层在实际使用中是否顺手——**如果分层本身不好用，自动化只会把难用的东西变快。**

## 8. 需要你补的信息

排期框架已经完整，缺的是这几个锚点：

1. **四级**：目标考试窗口（2026 年 12 月？2027 年 6 月？）、目标分数、当前水平
2. **雅思**：目标考期、目标分数、当前水平
3. **华为 HICP**：报名/考试窗口、是否已报名、目标（拿证还是够用）
4. **高数**：期末考期、当前薄弱章节
5. **Rust / 背书**：每周愿意投入多少（或者直接采用"Rust 优先 + 背书吃碎片"这个默认）

补齐这些，就可以把 §4 的阶段表填成真实日期，然后跑第一次完整的学期编排。
